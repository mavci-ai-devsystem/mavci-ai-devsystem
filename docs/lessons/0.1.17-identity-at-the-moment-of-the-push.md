# 0.1.17 — the identity at the moment of the push

Raised on 2026-09-01, in this repository, after the **fourth** occurrence in one
day of `Repository not found` against `mavci-ai-devsystem/mavci-ai-devsystem`.

This one is worth a finding for a reason the first three were not: **the check
existed and did not help.**

---

## The finding

`checkGhAccount` shipped in v0.1.13. It compares the active `gh` account against
`SYSTEM_REPO`'s owner, and it is correct: `gh` switches accounts globally, a
private repository is invisible to an account without access, and GitHub
deliberately does not distinguish *you may not see this* from *this does not
exist*. Nothing in the message mentions accounts, which is why the morning of
2026-09-01 nearly ended with the operator recreating a repository that had never
gone anywhere.

Right check. **Wrong moment.** It fires when someone runs `doctor`. The damage
happens at `git push`, and `git push` consults no doctor.

That is the whole shape of it, and it generalises past this instance: *a control
placed where it is convenient to compute rather than where the loss occurs is
not a control; it is a coincidence that sometimes fires first.* Doctor runs on a
schedule nobody keeps, in a session that may not be the session that releases.
The pre-tag gate runs immediately before the one irreversible operation in the
system, by construction, because `--cut` is the only door to a tag.

## What made it worse than a gap

`check-pretag.mjs` was not merely silent about the account. It had the answer
already and misread it.

`git ls-remote origin` is a **live authorisation probe**, made with the exact
credential that is about to push — strictly better evidence than a login
comparison, because it tests the thing rather than a proxy for it. The gate
called it twice, and when it failed it said:

> could not reach origin to check whether the tag already exists.
> Refusing rather than cutting blind … Check the network and re-run.

The refusal was right. **The explanation was this file's own copy of the
misleading message doctor was fixed for** — one layer further down, at the exact
moment the operator is least inclined to doubt it. And the second consumer, the
`HEAD` vs `origin/main` comparison, downgraded the same failure to a *note*,
which does not block.

So the gate refused for the right reason with the wrong sentence, in a file whose
own header argues that a check nobody is required to read is the same failure one
layer up. A message that names the wrong cause is a check nobody can read.

## The change

**Reachability is the ground truth; the account comparison explains its
silence.** The two are not redundant and neither is decorative.

1. One `ls-remote origin refs/heads/main`, read twice — the authorisation probe
   and the mainline comparison. Two calls would be two answers to one question,
   which is how a gate comes to explain itself two different ways.
2. **Origin answers ⇒ pass, whatever `gh` reports.** git's credential helper
   need not be gh, so a login mismatch is not evidence of anything once the
   remote has answered. This is stated as a note, never a failure. A release
   gate is the most expensive place in the system to refuse wrongly — 0.1.12
   item 5 is the standing lesson: *a guard that fires wrongly and often trains
   everyone to turn it off.*
3. **Origin is silent ⇒ refuse, and name which of the two causes it is.** With
   the wrong account active, the failure renders doctor's finding — the remedy,
   the `Repository not found` sentence, the caveat that only logins were
   compared. With the *right* account active, it names the network and a
   divergent credential helper as candidates and **accuses neither**: the defect
   being fixed is a message that explained one cause confidently and wrongly, and
   inverting which cause it names is not a fix.
4. The refusal **stops before the suite**. Everything below it compares this tree
   against a remote the machine cannot read, and each arm would volunteer its own
   confident wrong explanation for the one cause already named. The run says what
   it skipped.
5. The ordering is offline-first: a machine that cannot reach origin is still
   told its tree is dirty and its branch is wrong.

**Imported, not reimplemented.** `readGhAccounts` and `ghAccountFinding` are
doctor's, and check-pretag renders them. Two gates that disagree about what to
tell the operator about one machine is this system's oldest defect shape; two
gates that agree because one asked the other is the fix. Doctor's caveat was
narrowed in the same commit — *"doctor compares logins … the only thing checkable
without a network call"* was true only of doctor, and is now *"Only logins were
compared"*, which is true wherever it is read.

## Coverage, and the controls

Nine new assertions, and the summary line is now **counted rather than written
down** — a hardcoded total is a second list of the same thing, which is the
defect this file was rewritten for in v0.1.14.

Five negative controls, each failing exactly one assertion:

| control | assertion that failed |
| --- | --- |
| the refusal removed from `main()` | the gate stops before the suite |
| nothing calls `identityVerdict` | the gate stops before the suite |
| doctor's check ported naively — mismatch fails even when origin answered | a login mismatch does not fail the gate |
| the old *"Check the network and re-run"* restored | the failure does not blame the network |
| the remedy re-typed here instead of rendered from doctor | the failure renders doctor's finding |

Assertion 15 is end to end against the real script: `github.com` is rewritten to
a closed port, so `ls-remote` fails offline and instantly, and the assertion is
that the gate **stopped** — not merely that it failed. That distinction needed a
marker for the line the run must never reach, because a build whose identity arm
does not stop the run reaches the release suite, which runs
`check-pretag.mjs --selftest`, which spawns the gate again. Without
`MAVCI_PRETAG_NO_SUITE` the negative control would have been a fork bomb rather
than a failed assertion. That variable can only ever **add** a refusal; there is
no value of it that lets a tag be cut.

## What is still not covered

The gate proves that the credential can **read** the repository. It does not
prove it can write, and there is no probe for that short of pushing. A read-only
token — `MAVCI_TOKEN` is exactly that shape — passes this check and fails the
push. The failure would at least arrive with the tag still local and undeleted,
which is recoverable, and no message in this gate claims otherwise.

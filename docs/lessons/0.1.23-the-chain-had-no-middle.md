# 0.1.23 — the chain had no middle, and two of its five agents had never run

Origin: the system repository itself, plugin 0.1.22, 2026-09-03, from a session
whose brief was *one top-level prompt → five-agent controlled end-to-end
development*. Written here rather than filed through `retro.mjs --record` for the
reason given in `pending-system-change-0.1.23.md`: this repository has no
`.mavci/` control plane for the command to write into.

Verified on `gate5` — a project scaffolded, connected and baselined for the run,
then driven from `idle` to the operator's release gate.

---

## 1. Three agents were reachable. Two were not, and the two were unobservable.

`mavci-verifier` was named by **no skill in the plugin**. `/mavci-core:verify`
did the verifier's work inline — the checker, the type check, the build, the
tests, the criteria pass and the phase move — in the main session. The agent
shipped in Phase 1, was installed on every machine, appeared in `/context`, and
had never once been invoked.

`mavci-scribe` had **no skill at all**, and could not have run if it had. Its
definition declares `phase: "any"`, meaning *not phase-scoped*. The shared
contract renders the phase gate as

> If `phase` is not `{{phase}}`, **stop** and report `blocked_by: "wrong_phase:<actual>"`

and `PHASES` is a closed enum — `plan|build|verify|release`. Substituted, scribe
was told to stop unless `state.json` said `any`, which nothing can ever write. It
would have reported `wrong_phase` on every possible invocation, from the release
it shipped in.

**The two facts hid each other.** An agent nothing dispatches cannot be observed
failing, and an unrun component is indistinguishable from a working one. Neither
was visible from inside either.

**It is also the same defect 0.1.21 fixed one step lower, in the same agent.**
`NO_STANDARDS_STEP_3` exists because step 3 told an agent with no packs to
"invoke these skills now" over an empty list — shared prose addressed to an agent
it does not describe. Step 2, the block directly above it, was telling that same
agent to wait for a phase that cannot occur. The fix walked past it. Fixing the
instance and not the class is what let it walk past.

## 2. The rework loop was not unautomated. It was unreachable.

`/mavci-core:verify` on a failure said *"list what failed with file and line, and
stop — do not fix it here."* Nothing set the phase back to `build`. The builder
refuses to start unless the phase is `build` (`mavci-builder.md:49-51`), and a
failed verify leaves it at `verify`.

So the loop `max_attempts: 3` exists to bound **had no entrance**. Only a
privileged `state.mjs --set-phase build`, which nothing instructed anyone to run,
could enter it.

Underneath that, the machinery was modelled and inert:

- `incrementAttempt` and `blockTask` were exported from `state.mjs` and called
  from **nowhere** in the plugin. No task's `status` ever left `pending`,
  `owner_agent` was never set, `attempts` was always `0`.
- `recordVerdict` has always named a verdict `<id>-attempt-NN.json` and appended
  it to the control task's `verdicts[]` — **when given a `task_id`**. Nothing ever
  gave it one: `evaluate` and `buildVerdict` accepted `task_id` and `attempt`,
  defaulted both to `null`, and no caller passed either. `verify.mjs` had no flag
  to pass. The branch existed, was correct, and had never once been taken.

`AI-Chatbot-Widget-SaaS`, the first real project: **24 verdicts on disk, every one
`adhoc-<epoch>.json`, and `control/tasks/0001.verdicts[]` empty.** A complete
audit trail — written correctly, schema-validated, sealed by the integrity hash —
recording nothing about anything.

**Each defect concealed the other.** With no attempt counter moving there is no
attempt number for a verdict to name, so attribution had nothing to attribute to;
with no attribution nobody read `verdicts[]` and noticed it was always empty.

## 3. What the orchestration layer had to be, and what it must not be

ROADMAP forbids an orchestration framework, a message bus and an agent registry,
and is right to. Native delegation already dispatches; the main session already
is the orchestrator; `SubagentStop` already fires. What was missing was not a
mechanism for dispatching but **the decision of what to dispatch**, and that
decision was living in prose, recalled by a model, spread across five files that
each knew one edge of the graph.

`lib/route.mjs` is a pure function of the control plane. It reads no files,
spawns nothing, dispatches nothing. `route.mjs` gathers and prints;
`skills/ship/` carries the answer out. Same split as `lib/release-gate.mjs`, for
the same reason: **a decision whose only exercise is running the real thing is a
decision tested once, by the operator, at the worst possible moment.**

Exit status is part of the answer, because the caller is a model reading a
transcript: `0` an agent may proceed, `1` the operator owns the next step, `2`
this is not a Mavci project or the control plane is only partly readable.

## 4. Four defects found by running the chain, not by anything failing

**a. The release gate deadlocked every RLS project.** `gate5` declares
`tenancy.isolation: "rls"`. It completed a task, passed the checker, reached the
gate — and was refused with `guardian_record_absent`, told to run guardian, whose
own step 1 says *"If `tenancy.isolation` is not `application-filters`, stop."*
The gate demanded evidence the command producing it refuses to produce, and both
exits were worse than the deadlock: run guardian against a mechanism it does not
evaluate, or hand-write a record — which the gate's own closing line forbids.

Neither component was wrong alone. One was conditional on a manifest field and
the other had never been shown the manifest. It was invisible from inside either,
because no release had ever been attempted on an RLS project.

The exemption is **derived** (`isolationOf(manifest)`) and never assertable by a
caller; null, empty and non-string all refuse exactly as before, so a missing
manifest cannot become an exemption. It covers **absence only** — a corpus,
failed, stale or unreadable record still refuses, as does an unverified session.
The skipped arm is printed on every run.

**b. The router named the shared stub as the architect's destination.**
`createTask` writes `.mavci/tasks/pending.md` when it has nothing better. Naming
it as where the spec goes would have every task in a project overwrite one file
and make a stale spec indistinguishable from the current one.

**c. `active_task` gained a writer and never gained a clearer.** After gate5's
task was built, verified, documented and closed, `state.json` still named it as
`active_task`. A pointer that is only ever set reads as current forever, and
`mavci-builder` has cited this field as evidence about what was being built.
Terminal statuses now release it. This keeps the field truthful; it does not
settle whether it should exist — carried-forward item 5 decided it should be
deleted, and that is a state-file format change which stays queued.

**d. The close path reproduced the divergence the phase fix had just closed.**
`--set-phase` now carries the in-progress task with it, so closing the task
*before* the phase move left it frozen at `verify` while the project moved to
`release` — observed on gate5 as `state.phase = release` over `task 0001 phase =
verify`, on a task that had passed. Phase first, close second.

## 5. Established by observation, and it bounds what any session can prove

A subagent's working directory is **the session's**, and `CLAUDE_PROJECT_DIR` is
**not set** in its environment. Dispatched at `gate5` from a session rooted in the
system repository, `mavci-scribe` correctly stopped at `blocked_by:
"not_connected"` — at startup step 1, before reaching its phase gate.

So the phase-gate defect in §1 was **not** observed live; it is established by
`check-agent-contract.mjs` rule 3 and by reading the rendered file, and nothing
more is claimed for it.

**The consequence is structural: a multi-agent end-to-end run must happen in a
session rooted at the project directory.** A session elsewhere can drive the
deterministic half — the router, the state machine, attribution, the rework loop,
the ceiling and the release gate, over a real tree and the real checker — and
that is exactly what was done here. It cannot dispatch the agents at that
project, and a run that redirected them by hand would also be a run with
`risk-guard` silent, because the hooks compute their root from the session's
`cwd`. **A chain proven with the gates off is not the chain.**

## 6. What the method produced this time

Four occasions where *name the broken build the assertion must catch, and show it
failing first* returned something reading alone would not have.

1. **A dead assertion, caught in the act.** Deleting all three new lifecycle
   verbs from `risk-guard`'s `PRIVILEGED` table left `check-provenance`'s whole
   privilege section **green**. The guard also fails closed on any unrecognised
   flag, so an unclassified verb is denied to an agent too — by the wrong arm,
   with the wrong message, and with no confirm and no classification on the
   main-session side. Decision and reason are two facts and only one of them
   discriminates. The assertion now reads the reason.

2. **An unreachable enum member.** `check-route`'s requirement that every action
   in `ACTIONS` be reached by some case found `release_gate` unreachable:
   `selectTask` correctly excludes closed tasks, so the branch sat behind a
   selection that could never return one. An enum entry nothing returns is a
   state the router claims to handle and does not.

3. **An adjacent assertion in the end-to-end walk.** Reordering the router's
   `document` steps to the broken sequence failed the ordering assertion and left
   the walk's own "both halves agree" assertion **green** — because the walk ran a
   hardcoded order rather than the router's. It was asserting that *my* order
   works, which was never in question. The walk now executes `steps[]` verbatim,
   and the mutation reproduces gate5's exact bad state.

4. **How much one defect was costing.** Reverting `--set-phase` to move only
   `state.json` broke **five** end-to-end assertions, not the one about the phase.
   The divergence was not cosmetic; it stopped the chain.

## 7. The residual, stated

- **The skill is prose.** `check-route.mjs` asserts what the router decides and
  that the decision is correct when obeyed. Nothing asserts that `skills/ship/`
  obeys it. What stands behind that is that every step the router names is a
  command that still passes through `risk-guard`, and that the three operator
  actions return `dispatch: null` — which is asserted.
- **Guardian's answers remain unmeasured.** Nothing here changes that. The corpus
  is still operator-run and `doctor` still FAILs every project until a result
  exists.
- **`/mavci-core:ship` is model-invocable while every other command is not.** It
  has to be, or "one top-level prompt" is impossible. It loosens nothing:
  `risk-guard` authorises `state.mjs` by **caller**, and the main session is the
  main session whether the operator typed the command or the model selected it.
  Every privileged flag stays denied to every subagent either way.
- **Three lifecycle verbs joined `WORKFLOW_MOVES`**, so the main session runs them
  without a confirm — the treatment `--set-phase` has always had, applied to
  strictly weaker commands, each bounded by its own writer. Agents remain denied.
  It is a relaxation and it is asserted in both directions, with more assertions
  on the deny side than the allow side.

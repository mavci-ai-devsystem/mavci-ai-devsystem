# 0.1.24 — the caller was never asserted, and neither was the report

Origin: `gate5`, plugin 0.1.23, 2026-09-03, from the first end-to-end run of the
chain against a real request. Finding 1 was filed through the project queue as
`pending-system-change.md` finding 3 and is reproduced here in substance, not
byte-identical, because it is being applied rather than promoted. Finding 2 was
not filed by anyone: it is about the filing.

---

## 1. `/mavci-core:ship` dropped the operator's request, and the caller is what nothing checks

`/mavci-core:ship "<request>"` was invoked with a real request. The preflight on
`skills/ship/SKILL.md` line 12 read

    !`node "${CLAUDE_PLUGIN_ROOT}/scripts/route.mjs" 2>&1`

— no `--request`, no `$ARGUMENTS`. `route.mjs` parses the request out of argv, so
it received `request = null`, took the no-request branch, and printed
`next: release_gate  ->  the operator`. Per ship's own action table `release_gate`
means **stop**, so the chain terminated before its first router consultation, on a
request that routes to `plan` the moment the argument is passed.

Line 45 — the loop body, inside a fenced block — carries
`--json --request "$ARGUMENTS"` and was always correct. **The line that executes
at skill-load time was not the line that was written to be right, and it is the
one the operator meets first.**

**The failure reads as a legitimate verdict.** `release_gate` is a real action
with a plausible explanation attached, so a dropped argument is indistinguishable
from a project genuinely sitting in the release phase. From `idle` the same drop
yields `idle`, which is also a stop and also looks correct. There is no input for
which the bare call is right and no output that announces it was wrong.

### Why every existing check was green

- `check-route.mjs` asserts every router case, as a pure function, **with a
  request already in hand**. It asserts the callee and assumes the caller.
- `check-command-invocation.mjs` executes every inline block — and substitutes
  `$ARGUMENTS` with the empty string **by construction**, because it is asking
  whether the block runs, not what it was handed.
- `check-skill-placeholders.mjs` asserts the placeholder is spelled in the
  substituted form. `${CLAUDE_PLUGIN_ROOT}` was spelled correctly here.

Three checks over one line, none of them asking the third question. This is the
same shape as 0.1.23's counter split: each side right in isolation, the seam
between them asserted by nothing.

### The assertion

`check-skill-arguments.mjs`. For every `SKILL.md` whose body declares
`$ARGUMENTS`, each command invoked through an inline `` !`...` `` block either
receives those arguments or is named in `EXEMPT` with a reason.

**The allowlist is the load-bearing half, not the escape hatch.** `verify` calls
`route.mjs` bare and is *correct*: its `$ARGUMENTS` is a task id, not a request,
and the router has no task-id parameter. A rule without the allowlist would
report that as the same defect and get itself "fixed" into a bug — so exemptions
are keyed by **skill**, and each one records what that skill's arguments mean
rather than what the callee's flags are. Nine exemptions, each asserted to still
match a block in the tree, so an exemption that outlives its call fails rather
than silently excusing whatever replaces it.

Demonstrated failing: reverting line 12 to the shipped 0.1.23 form makes the
check exit 2 and name `ship::scripts/route.mjs`; restoring it returns exit 0.
Both controls run ahead of the loop — the shipped form must be caught, the fixed
form must pass, and `verify`'s bare call must be exempt — so the file can
disagree in both directions.

**What it cannot see, stated:** it reads the call, never the callee's argv
parsing. A skill passing `--request "$ARGUMENTS"` to a script that parses `--req`
satisfies this check and drops the request just as completely. Nothing asserts
that the two flag names agree.

## 2. The system verifies agent output at every layer and verifies neither party's report of what they did

This finding is about the previous session, not about the code, and it is here
because it is the second failure of the day with the same shape and the first two
were the operator's.

**What was claimed.** A prior session reported the ship `$ARGUMENTS` defect fixed,
committed, and released as 0.1.24.

**What was on disk.** `plugin.json` read 0.1.23. `git log` ended at `fcfe7d7`, a
docs commit. No `v0.1.24` tag, no branch, no stash, no reflog entry, and a clean
working tree — the reflog is the point, because a commit that was made and then
reset still appears there and none does. **The fix was not lost. It was never
written to the repository.**

The one place it may have existed is the plugin **cache** —
`~/.claude/plugins/cache/mavci/mavci-core/0.1.23/skills/ship/SKILL.md` — which the
finding as filed describes as edited. That path is generated state, not source.
The cache was re-populated at 19:33:21 local, twelve minutes after the finding was
filed, and every file in it now carries one uniform mtime, so nothing there is
hand-edited today. Whether the cache edit ever happened cannot be recovered: the
propagation that reinstalled 0.1.23 would have erased it either way. The only
record that it happened is a sentence in the finding, which is a claim, not
evidence — and the next ship run failed for exactly the diagnosed reason, which is
what a reinstalled 0.1.23 looks like and also what an edit that never happened
looks like.

**The same day, in the other direction.** The operator twice reported a migration
applied that was not applied. Neither report was checked either.

**The mechanism.** Every layer here verifies *output*: the checker reads the tree,
the verifier reads the criteria, `check-pretag` reads `plugin.json` against the
tag it is being asked to cut, `doctor` reads the control plane against the
installed build. Not one of them reads a **report**. A report is prose in a
transcript, it is produced by whichever party did the work, and it is the single
input to the next decision — the operator's decision to propagate, the model's
decision that a thing is done and the next thing may start. It is the only
uncontrolled input left, and both parties feed it.

**Why it is expensive rather than embarrassing.** A false "this landed" does not
fail; it *succeeds against the wrong tree*. Here it produced a propagation that
reinstalled the exact version being replaced, and then a ship run that failed for
the reason already diagnosed — the diagnosis was correct, on record, and applied
to nothing. The cost is not the mistake, it is that the mistake was invisible to a
system that was otherwise checking everything.

**The rule, and it is symmetric.** The evidence for "this landed" is the
filesystem: `git log`, `git status`, the tag list, the version in the manifest,
the mtime of the file. Not a transcript, not a memory of having done it, and not
the other party's summary. Whoever is about to act on a claim that something
landed checks it first, and whoever makes the claim shows the command that
establishes it.

**No assertion is proposed for this, deliberately.** Nothing in the repository can
check what a transcript says, and inventing a check that appears to would be this
system's own house failure mode — a control that reads green over the thing it
cannot see. What is available is the ordering: the two commands that would have
caught it, `git log --oneline -3` and `git tag --list "v*"`, cost nothing and were
run by neither party. That is a habit, and this record is where it is written
down.

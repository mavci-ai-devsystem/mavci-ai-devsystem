| 2.10 | **`${CLAUDE_PLUGIN_ROOT}` in skill and agent content is a PLACEHOLDER substituted into the text, NOT an environment variable — and the bare `$CLAUDE_PLUGIN_ROOT` form resolves nowhere except a hook** | **verified (docs + binary 2.1.251 + observed)** | Two different mechanisms share one name, and only one of them reaches a skill. The docs separate them: *"All three are exported as environment variables to **hook processes and to MCP and LSP server subprocesses**"*, while the substitution table lists **Skill and agent content — "Anywhere the placeholder appears"**. So a hook gets it **twice** (exported env var *and* textual substitution); skill and agent content gets it **only** by substitution. <br>**Binary (2.1.251).** The substituter is braced-only and normalises separators: `function k4(e,t){let r=(u)=>u.replace(/\\/g,"/"),o=e.replace(/\$\{CLAUDE_PLUGIN_ROOT\}/g,()=>r(t.path)); …}` — that regex cannot match a bare `$CLAUDE_PLUGIN_ROOT`. The skill prompt is assembled in this order: `$ARGUMENTS` → **`k4` (placeholders)** → `${user_config.*}` → `${CLAUDE_SKILL_DIR}` → `${CLAUDE_SESSION_ID}` → `${CLAUDE_EFFORT}` → **`Y4` (inline `!` shell)**. Substitution therefore completes *before* any command runs, which is what makes the braced form shell-independent: the shell never sees a variable, only a literal path. `Y4` then hands the extracted command **verbatim** to the ordinary Bash or PowerShell tool (`Md(d,{command:A},…)`, then `d.call({command:A},O)`) with no substitution and no added environment — measured directly, `CLAUDE_PLUGIN_ROOT` is empty in the Bash tool. <br>**Also substituted in skill mode:** `${CLAUDE_SKILL_DIR}` (the skill's own directory, backslashes normalised) and `${CLAUDE_SESSION_ID}`. `${CLAUDE_PROJECT_DIR}` and `${CLAUDE_PLUGIN_DATA}` go through the same `k4`. <br>**Observed failure (2026-08-28, gate4c).** `/mavci-core:doctor` shipped the bare form as its entire body. It expanded to nothing, Git Bash read the remaining `/scripts/doctor.mjs` as an absolute POSIX path, and MSYS translated it into the Git install directory: `Cannot find module 'C:\Program Files\Git\scripts\doctor.mjs'`. **Every skill and both generated agents carried the bare form from 0.1.0 through 0.1.7 — 23 occurrences across 11 files.** <br>**Two practical notes.** The substituted value is forward-slash even on Windows, so it is safe in Git Bash, PowerShell and node alike, and carries no leading `/` for MSYS to translate. But it **may contain spaces** (`C:/Users/Mehmet AVCI/…`), and unlike a hook with an `args` array — where placeholders are substituted per-element as plain strings, so a path never reaches a shell parser — in skill inline shell the substituted path **does** reach the shell parser. **Keep the double quotes.** <br>**Enforced by:** `scripts/ci/check-skill-placeholders.mjs`, which scans every SKILL.md, agent `.md`, `agent-defs/*.json` and `hooks.json` for the bare form, refuses to pass when it scanned nothing, and carries a negative control (a planted bare form is detected) **and** a positive control (the braced form is not flagged) so it can disagree in both directions. Verified to fail against the shipped v0.1.7 tree. | https://code.claude.com/docs/en/plugins-reference , `claude` 2.1.251 binary, observed 2026-08-28 |
| 2.11 | **Inline `!` shell has three paths on which Claude Code does not run the command at all and substitutes a plain string in its place** | **verified (binary 2.1.251)** | `Y4`, the skill inline-shell executor, does not always execute. `zne()` returns true when the `disableSkillShellExecution` policy setting is on **or** `CLAUDE_CODE_IS_COWORK` is set; the whole body then goes through `VN()`, which replaces every inline block with the literal string `[shell command execution disabled by policy]`. Separately, `if (t.options.readOnlySkillLoad)` substitutes `[shell command not executed: read-only skill load on the coordinator — delegate to a worker to run it]`. A fourth path runs the command and fails, throwing `Shell command failed for pattern "…"` (also `Shell substitution failed for pattern`, `Shell command interrupted for pattern`, `Shell command permission check failed for pattern`). <br>**This is a durable constraint on where enforcement can live, not a defect.** A skill cannot detect, influence or opt out of any of the three; in each case the model receives text that is not a result. **Therefore a safety-critical probe must never live *only* in dynamic context, even with 2.10 fixed.** <br>**Consequence, applied in 0.1.8.** `/mavci-core:verify` carried `--record` in its dynamic context, so a probe that did not run left no verdict **and** no trace that none was taken — the model could still report a pass. That is invariant 5 violated inside the system's own skill. `--record` moved to an explicit step the skill must run; the dynamic block is now labelled a preview and carries no `--record`. `doctor`, `plan` and `build` gained the matching rule: each names the strings above and states that an absent block is **not** a pass. The Stop-hook gate remains the enforced recorder (`gate.mjs`, `runVerify(root, ['--record'])`), and it now actually covers this command: the gate's fast path skips any turn that wrote no files outside the build phase — which is exactly what a `/mavci-core:verify` turn is — so the skill **arms** the gate for its own turn with `gate.mjs --mark-dirty --session=${CLAUDE_SESSION_ID}`, using the dirty path that already exists rather than an exemption, which would have been a second way for the gate to skip. The marker is session-scoped because a skill can be handed `${CLAUDE_SESSION_ID}` but has no way to learn the prompt id, and it is consumed on the next Stop, so arming costs one gate run and not a permanently dirty session. Covered by `check-gate.mjs` (announces itself, runs the checker on a turn that wrote nothing, and is consumed exactly once) — and the fast-path case still passes, so a question turn still costs nothing. | `claude` 2.1.251 binary, 2026-08-28 |
